My home network runs on two FreeBSD routers in a CARP pair, with several
VLANs behind them: a main LAN, guests, IoT devices, and a backplane for the
servers. IPv4 is the easy part. IPv6 is where it gets interesting, because
the addresses aren't mine: my ISP hands out a **delegated prefix** over
DHCPv6, it can change, and everything downstream has to follow.

The tool doing that work is **dhcpcd**. This post walks through the
configuration that's been running for a while now, and the lessons behind
each line.

## The whole configuration

```
logfile /var/log/dhcpcd/dhcpcd.log
noipv6rs
nohook resolv.conf, hostname, ntp.conf, test
duid
persistent
require dhcp_server_identifier
slaac private
option interface_mtu
denyinterfaces lan guests iot backplane pflog0 # generated by Ansible

interface voip
	noipv6
	nodhcp6
	nogateway
	nooption routers

interface internet
	noipv4
	ipv6only
	ipv6rs
	ia_pd 1 lan/0/64/0 guests/1/64/0 iot/2/64/0 backplane/3/64/0
```

Short, but nearly every line is there for a reason.

## Opt in, interface by interface

The global section starts defensive. **`noipv6rs`** turns off router
solicitation everywhere, and **`denyinterfaces`** tells dhcpcd to leave the
internal interfaces alone entirely: on a router, those are the networks you
*serve*, not the ones you obtain addresses from. In my setup, Ansible builds
that list from the host's interfaces, excluding the two that dhcpcd should
manage, so a new VLAN can't accidentally end up with dhcpcd running a client
on it.

**`nohook resolv.conf, hostname, ntp.conf`** stops dhcpcd from rewriting
files the router manages itself: it runs its own DNS resolver, and the
hostname and NTP servers are configuration, not something an ISP should
change.

**`duid`** makes dhcpcd identify itself with a DHCP Unique Identifier, which
is what lets the ISP recognize the router across reboots and, ideally, give
it back the same prefix.

**`persistent`** keeps addresses and routes configured when dhcpcd exits.
Without it, restarting dhcpcd, for an upgrade or a configuration change,
briefly tears down IPv6 on every VLAN.

## The upstream interface

The `internet` interface carries only IPv6 in my case (IPv4 arrives over
PPPoE), hence **`noipv4`** and **`ipv6only`**, and it re-enables router
solicitation with **`ipv6rs`**, since that's where the ISP's router
advertisements come from.

Then the line that does most of the work:

```
ia_pd 1 lan/0/64/0 guests/1/64/0 iot/2/64/0 backplane/3/64/0
```

`ia_pd 1` requests a delegated prefix, identified as `1`. Each
`interface/sla_id/prefix_len/suffix` entry then carves a subnet out of it:
`lan` gets subnet 0 as a /64, `guests` subnet 1, and so on. With a /56 from
the ISP, that leaves 252 more /64s for future VLANs.

The last field, the **suffix**, decides the router's own address on each of
those subnets. A fixed value, like `1`, would give every interface a
predictable `::1` address. Setting it to **`0`** lets **dhcpcd generate the
global unicast address itself**, the same way SLAAC would, and with
`slaac private` in the global section, that's a stable but opaque interface
identifier, rather than one derived from the MAC address.

Using **/64** on every network isn't a matter of taste: it's the size SLAAC
requires, so every device can build its own addresses, and rotate them with
privacy extensions, without any DHCPv6 server on the LAN.

## The VoIP VLAN: take the address, not the route

My ISP delivers telephony on a separate VLAN, which hands out an IPv4
address over DHCP, along with a default route. Accepting that route would
send the whole network's traffic down the VoIP VLAN. So:

```
interface voip
	noipv6
	nodhcp6
	nogateway
	nooption routers
```

**`nogateway`** stops dhcpcd from installing a default route, and **`nooption
routers`** stops it from even requesting one. The VoIP-specific routes come
from the ISP over RIP instead, which is a story for the next post.

## Advertising the prefix inside: the exit hook

Getting addresses onto the router's interfaces is half the job. Devices on
each VLAN learn the prefix from **router advertisements**, sent by `radvd`,
whose configuration has to contain the current prefix, and the DNS resolver
address (RDNSS) for each network.

Since the prefix can change, that configuration is generated by dhcpcd's
**exit hook**, a shell script dhcpcd runs after every event. The trick that
made it reliable was making it act only when something actually changed:

```sh
# Exactly one usable global address per interface:
# skip deprecated, tentative and detached ones
addr6() {
	/sbin/ifconfig "$1" inet6 | /usr/bin/awk '/inet6 2001:db8/ && !/deprecated|tentative|detached/ { print $2; exit }'
}

LAN=$(addr6 lan)
IOT=$(addr6 iot)
SIG="$(addr6 internet) ${LAN} ${IOT} $(addr6 guests) $(addr6 backplane)"
STATE="/var/run/dhcpcd-hook.state"

if [ -n "${LAN}" ] && [ -n "${IOT}" ] && [ "${SIG}" != "$(cat ${STATE} 2>/dev/null)" ]; then
	# regenerate radvd.conf, update firewall tables, DNS records...
	echo "${SIG}" > "${STATE}"
fi
```

Two details matter here:

- **The signature.** dhcpcd calls the hook for many reasons: renewals,
  router advertisements, carrier events. Comparing a "signature" of the
  current addresses with the last one seen means the expensive work
  (regenerating configuration, reloading the firewall, updating DNS records)
  runs only when addresses really changed.
- **Skipping deprecated and tentative addresses.** When a prefix changes,
  an interface briefly holds both the old address, marked `deprecated`,
  and the new one, still `tentative` while duplicate address detection
  runs. An early version of the hook picked whichever came first, and
  occasionally published the old prefix. Filtering them out made it pick
  exactly the address that's actually usable.

## Two routers, one prefix

Both routers run this configuration. After a change, the hook also copies
the generated files that the other router needs (firewall tables, the
reverse proxy's trusted addresses) to its peer and reloads them there, so
whichever router is CARP master serves consistent configuration.

## Takeaways

- **Opt in per interface.** `noipv6rs` and `denyinterfaces` globally, then
  enable exactly what each upstream interface needs.
- **`persistent` is essential on a router,** or every dhcpcd restart is an
  IPv6 outage.
- **Let `ia_pd` do the subnetting,** and keep every network at /64.
- **Make hooks idempotent.** Compare state before acting, and be precise
  about which addresses count as current.
